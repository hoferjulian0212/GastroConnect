1. SYSTEM ZIEL
GastroConnect ist kein reiner B2B Marketplace mehr.
Es entwickelt sich zu einem:
“Inventory + Perishability + Decision Engine System für Lebensmittel-Lieferanten”
Ziel:
Verderb minimieren
Umsatz optimieren durch dynamische Aktionen (Rabatte)
Lagerdaten + ERP Daten + menschliche Einschätzung kombinieren
Entscheidungen priorisieren statt nur Produkte anzeigen
2. KERNPROBLEM DAS GELÖST WIRD
Lieferanten verlieren Geld durch:
Verderb von Lebensmitteln
zu langsame Reaktion auf Ablaufdaten
fehlende Transparenz über Lagerzustand
keine priorisierte Entscheidungsübersicht
manuelle, unstrukturierte Rabattsetzung
3. WICHTIGES NEUES SYSTEMPROBLEM (CRITICAL GAP)
Aktuell fehlt im System eine zentrale Datenkomponente:
Es wird NICHT systematisch getrackt, wie lange ein Produkt noch haltbar ist bzw. wie der echte Shelf-Life Status pro Charge ist.
Das bedeutet:
keine präzise Haltbarkeitslogik im Backend
keine echte Zeit-zu-Verfall Berechnung pro Batch
keine differenzierte Produktqualität über Zeit
fehlende Grundlage für dynamische Preislogik
👉 Das ist ein fundamentaler Missing Layer im Systemdesign.
Das Backend muss erweitert werden, um:
Shelf-Life / MHD pro Charge korrekt zu speichern
Zeitverlauf der Produktqualität zu berechnen
Qualitätsverfall dynamisch abzubilden
