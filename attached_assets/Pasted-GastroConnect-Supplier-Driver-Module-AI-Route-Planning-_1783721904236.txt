GastroConnect – Supplier Driver Module & AI Route Planning (South Tyrol Only)

Design and implement a completely new user role called Supplier Driver. This is not a small feature but a complete workflow that connects Supplier Office, Drivers and Restaurant users into one seamless delivery ecosystem.

The entire UX should feel comparable to Apple, Linear, Stripe and modern logistics software: clean, minimal, extremely intuitive, with premium animations, micro-interactions and fast performance.

⸻

New User Roles

Supplier Office (existing supplier company)

Supplier administrators and office employees should be able to:

* View all incoming orders.
* Accept, reject and process orders.
* Edit orders before shipment if necessary.
* Change order statuses.
* Assign deliveries to drivers.
* Create delivery routes manually or with AI.
* Monitor all active drivers live.
* Chat internally with drivers.
* View delivery history and analytics.

⸻

New User Role: Supplier Driver

Create a completely separate dashboard optimized for mobile first.

The driver should only see information relevant to deliveries.

Main navigation:

* Today’s Deliveries
* Route Planner
* Map
* Chat
* Delivery History
* Profile

No unnecessary office functionality should be visible.

⸻

Driver Dashboard

The home screen should immediately show:

“Today’s Deliveries”

Each order appears as a modern card.

Every card contains:

* Order number
* Restaurant name
* Address
* Contact person
* Phone number
* Delivery window
* Order value (optional)
* Number of crates/packages
* Current status
* Priority indicator
* Notes from supplier

Cards should be clean with large touch targets.

⸻

Manual Route Planning

Drivers should be able to reorder today’s deliveries using drag & drop.

Example:

1. Hotel A
2. Restaurant B
3. Hotel C
4. Restaurant D

Simply drag cards up and down.

Animations should be smooth and satisfying.

⸻

AI Route Planning

This should become one of GastroConnect’s flagship features.

A button:

“Optimize Route”

When pressed, AI should calculate the fastest delivery order.

The calculation should use:

* Google Maps travel times
* Live traffic
* Road closures
* Construction
* Accidents
* Current congestion
* Estimated arrival times

The AI should continuously update during the day if traffic conditions change.

Example:

An accident occurs near Bolzano.

Instead of continuing the original route, the AI suggests a better order automatically.

Driver receives:

“Faster route found. Saves approximately 14 minutes.”

Accept button.

Decline button.

Delivery Workflow

Restaurant places order.

↓

Supplier receives order.

↓

Supplier accepts order.

↓

Supplier prepares order.

↓

Status:
Preparing

↓

Status:
Ready for Delivery

↓

Supplier assigns driver.

↓

Status:
Out for Delivery

At this moment the order appears automatically inside the driver’s dashboard.

The driver now owns this delivery.

Once the supplier changes the order to “Out for Delivery”:

The restaurant sees:

Driver name

Optional driver photo

Live vehicle position

Moving vehicle on map

Estimated arrival time (ETA)

Distance remaining

Current delivery status

Examples:

Preparing

Driver Assigned

Leaving Warehouse

On the Way

Arriving Soon

Delivered

The driver’s location should update live.

ETA should automatically update using Google Maps.

UI & UX Requirements

The interface should feel world-class.

Use:

* Premium animations
* Smooth transitions
* Glassmorphism where appropriate
* Clean cards
* Rounded corners
* Beautiful loading states
* Skeleton loaders
* Interactive maps
* Floating action buttons
* Modern icons
* Haptic-friendly interactions
* Responsive layouts
* Mobile-first design
* Dark mode
* Light mode

The experience should be extremely easy to understand even for drivers who are not very experienced with technology.

The goal is to create one of the most intuitive supplier delivery systems for gastronomy.

All code should be modular, scalable and production-ready so future expansion beyond South Tyrol is easy.
