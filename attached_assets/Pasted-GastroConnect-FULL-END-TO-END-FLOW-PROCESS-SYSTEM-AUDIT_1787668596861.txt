2. CORE PRINCIPLE

The entire application must behave like one coherent system.

There must never be a situation where:

* one page says an order is confirmed
* another page says it is pending
* another page still allows confirmation
* another page allows cancellation
* the supplier sees one status
* the restaurant sees another status
* the driver sees a different state

All state transitions must be consistent across the entire application.

⸻

3. CRITICAL RULE: ONE CLEAR ACTION PER STATE

Audit every workflow state.

For example:

Supplier receives order

The interface should make the next logical action obvious.

It must NOT contain:

* two competing confirmation buttons
* duplicate buttons with slightly different meanings
* old and new confirmation flows
* actions that lead to the same result
* actions that appear available but are invalid

For every important state:

What is the one thing this user should logically do next?

The UI should make that obvious.

Secondary actions should exist only when genuinely necessary.

⸻
